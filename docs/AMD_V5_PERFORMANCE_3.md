## 产品改动

| 配置 | 冻结 V5 | 8.9 分版本 | 本版 |
| --- | ---: | ---: | ---: |
| graph_degree | 128 | 128 | 64 |
| intermediate_graph_degree | 256 | 192 | 64 |
| nn_descent_niter | 100 | 64 | 4 |
| itopk_size 下限 | 512 | 512 | 4096 |
| search_width | 4 | 32 | 32 |
| num_random_samplings | 库默认 | 4 | 1 |
| 搜索算法 | 库默认 | 库默认 | MULTI_CTA |
| max_queries | 库默认 | 库默认 | 128 |

输出图和中间图减少建图工作，较大的候选集合补偿检索覆盖。`itopk_size` 仍至少为
`4*k`；大于 SINGLE_CTA 支持范围后显式使用 MULTI_CTA。所有数据、维度和查询
使用同一配置，没有按数据身份、评测阶段或隐藏答案分支。输入、图数据和距离保留 FP32。

主程序新增同步的大栈执行器，复用一个 32 MiB pthread，替代每次建图、查询和快照操作
都创建/回收线程的路径。提交者等待自己的任务完成，支持重入、异常恢复和停机；
GPU 任务在进程内串行执行，没有宣称提升多客户端并发吞吐。GPU bridge 复用每个索引的
查询/结果缓冲区及搜索参数，互斥保护查询和快照，扩容失败保留原工作区，释放时回收缓存。
惰性重建先准备新 bridge 和 ID 映射，再一起替换，避免异常留下不一致状态。

仍为真实 GPU NN-descent 建图及 hipVS/cuVS CAGRA 搜索。六个 C ABI 导出、快照格式和
CPU VSAG 基本功能保留；没有加入内存池、混合精度或 CPU 替代检索。标准 bridge 构建
增加 `-pthread`，不要求评测端新增自定义开关或下载依赖。

## 完整 SQL 测量

Radeon Cloud，gfx1100、ROCm 7.2.4，16 CPU / 55 GiB 配额。冻结 V5 主程序从源码
完成 Release 构建；候选主程序和 bridge 从本轮最终源码重新构建。初轮完整构建中，
未跟踪的生成文件 `type_name.c` 为零字节导致链接失败；使用原 V5 生成器和规范头文件
恢复后构建通过。构建失败、恢复和最终编译日志均保留，没有修改跟踪生成器或锁文件。

每次 SQL 运行使用独立新数据库，导入不计入构建时间；冷 DDL 至第一条固定合法查询
完成为构建耗时。数据为 SIFT 前 250K/128 维与 Gaussian250K/256 维（种子 20261102），
每组 Top-10/100 分别执行全部 4096 条 SQL 查询，检查恰好 k 个合法、互不重复的 ID。
随后停服重启，对同一完整查询集再次验证。真值使用独立 FP64 穷举 L2 计算。

执行顺序为基线 1、候选 1、候选 2、基线 2；未做随机排序，不挑选最快一轮。
`nq=4096` 在这里表示 SQL 查询数量；追踪发现该正常 SQL 路径逐条调用 CAGRA
`nq=1`，不将 4096 条 SQL 偷换成一次 C ABI 批量调用。私有正式 harness 未公开，
因此不声称这里完全复刻其 SQL、预热、计时和重复策略。
