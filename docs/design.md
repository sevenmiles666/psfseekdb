# 存储、执行与恢复

## 文件和主键树

所有数据写入 `/data/database.mvdb`。前 8192 字节为两个根槽，每槽间隔 4096 字节，槽头包含魔数、代数、目录位置/长度、目录校验和及槽头校验。后续区域追加二进制记录、不可变树页和 CBOR 表目录。整数采用小端 int64，字符串带字节长度，向量采用小端 IEEE float32。

主键树为自研 B+ 树，页面固定 4096 字节、最多 128 项。内部项保存子树最大键和子页位置，叶子项保存键及记录位置/长度；有序遍历得到主键升序记录。更新复制受影响路径，批次内复用私有页面；溢出页面二分。删除移除空子树，目前不合并非空的低占用页面。

内存页缓存最多约 2048 页；私有页达到 512 页后写入文件，追加缓冲最多 1 MiB。行记录按需读取，数据不随数据库整体常驻内存。表目录仍全部驻内存，极端表数量未验证。单条记录读取上限 128 MiB。

## 事务与语句边界

只支持单进程、单客户端、最多一个显式事务；文件用排他 flock 防止第二个写进程。引擎保留已提交目录、事务当前目录和语句开始目录。成功修改只发布新的可见树根，SELECT 使用当前目录，因而能读到自己的修改。

每条修改语句记录文件追加位置。如果多行 INSERT 中途重复主键，或者类型校验失败，将目录回到语句开始版本并截断本语句的追加内容。显式 ROLLBACK 则回到事务开始位置和已提交目录。正常 shutdown 和 stdin EOF 也回滚未提交事务。

例如，已有主键 1 时，一条 `INSERT INTO t VALUES (2),(1)` 失败后仍只有 1；分为两条自动提交语句插入 2、再插入 1，失败后为 1 和 2。该对比已实际执行并记录。

## 提交、恢复和压实

成功修改自动提交，或显式 COMMIT 时：

1. 把私有页和新目录追加到文件，刷新追加缓冲。
2. fsync 数据文件，确保新根依赖的内容先完成同步。
3. 覆写交替根槽，写入新代数和校验；再次 fsync。
4. 更新进程内已提交目录，然后返回成功。

I/O 错误会返回错误并退出，避免继续使用提交状态不确定的进程。发布和压实位于语句回滚处理之外，避免后续维护失败撤销已经同步的根。

启动校验两个槽及目录，选择最新有效代数，截断未发布尾部。树页读取时校验页面校验和；行记录本身不另带校验和。恢复是可重复的：截断后再次异常退出，再启动仍能使用同一已提交根。进程强杀测试不模拟存储硬件的全部断电行为，持久性依赖文件系统正确实现 fsync 和原子 rename。

默认文件超过 64 MiB 后，每 128 次提交检查有效数据与文件大小；废弃空间充足时，在 `/data/compaction-work` 重建有效行和树。新文件同步后原子 rename 替换主文件，再同步父目录。崩溃后只会选中旧文件或新文件，启动删除残留工作目录。压实需要额外磁盘空间，磁盘不足会停止运行；不支持在线并发压实。`MVDB_COMPACT_THRESHOLD` 可降低测试阈值。

## 查询与向量

完整解析 SQL 后才执行。WHERE 主键等值使用树定位，其他条件扫描记录；字符串合法 UTF-8 的字节序等同 Unicode 码点序。比较用的字符串常量不受列最大存储长度约束。未知语法、列或不支持的类型会显式失败。

无排序查询过滤后直接投影；排序查询保存不可变记录的位置，在选出最终结果后投影。有 LIMIT 时使用 TopK 堆，无 LIMIT 时最终结果全部排序。候选不保存大文本投影；排序键缓存共享估算预算为 8 MiB，单候选最多 4 KiB，超出时比较器按记录位置读取，最多同时加载两行。相同排序键使用主键升序稳定判定。响应上限只约束最终输出，不因中途将被淘汰的候选报错；无 LIMIT 时所有匹配记录都是最终结果，可以提前累计输出大小。响应保留协议开销并限制在 16 MiB 内，超限返回错误。没有实现 JOIN、聚合、NULL、子查询、ALTER TABLE、嵌套事务和主键更新，也没有实现外排；超大排序键的比较读取可能增加 I/O。

向量先转为有限 float32，L2 使用 double 累计平方差。缓存和普通路径都比较开平方后的 double 距离；平方和不同但开平方舍入相同的距离按主键并列处理，避免建索引改变精确结果。每表至多一个向量列。CREATE VECTOR INDEX 保存元数据；检索准备一个全引擎共享、估算上限 32 MiB 的缓存，保存向量和过滤所需普通列。缓存完整时连续扫描向量，过滤发生在 TopK 前；超出预算则释放该缓存，改为磁盘扫描。内存预算采用保守估计，不代表 allocator 的精确字节上限。

修改、回滚和压实都会使向量缓存失效；恢复后在 ready 前重建已声明索引的缓存。多个索引表会按需切换同一个预算，不把表数量乘为缓存预算。当前 `ann` 复用精确路径，召回率语义为精确结果；没有宣称实现 HNSW/IVF 或次线性检索。大数据查询和恢复的耗时仍需按正式规模验收。

## 代码入口

`minivectordb/main.cpp` 负责严格 JSONL、ID 和响应；`sql.hpp` 负责 SQL、类型和行编码；`storage.hpp` 负责文件、发布和 B+ 树；`engine.hpp` 负责事务、查询、向量缓存和压实。`tests/` 中的参考模型、资源测量和基准不进入镜像。

SQL 长文本的普通字节分块扫描，遇到引号和反斜杠后继续逐个处理转义；UTF-8 的 ASCII 段以 8 字节检查高位并计数，非 ASCII 仍按完整 Unicode 标量校验。使用 memcpy 读取避免未对齐访问，没有架构专用 SIMD 指令。
