# Full-text pipeline optimization

The candidate builds on commit 23798003eeb4113babfcf55064d44793b95be838. It preserves the official benchmark, input data, SQL and expected results.

* Default-property calls to the built-in IK and BENG tokenizers can reuse a successful binary JSON result for identical input bytes, parser bytes, NULL flags and input collation. Arguments are evaluated on every call. Custom properties, invalid inputs and oversized values use normal tokenization. The eight-entry per-worker memo bounds retained payload to 256 KiB; cache allocation failure leaves SQL behavior unchanged. Dictionary hub identity and a generation counter invalidate the memo. Results are repacked for the current expression's JSON/LOB representation.
* Natural-language postings used only as a Boolean filter bypass per-document relevance dimension collection. Up to four sorted postings streams retain their current IDs and advance all streams supplying the previous minimum; larger unions keep the ordered heap. Both paths preserve order, duplicate suppression, storage visibility and document lookup. Scoring, Boolean mode and additional relevance filters keep their original path.
* FTS auxiliary build tasks retain their requested parallelism. Storage range planning respects that degree even when a small input tablet has expensive generated-column processing. Storage range boundaries and the existing maximum parallel index still bound the split.
* FTS builds select an automatic degree of up to four workers, bounded by the configured CPU count (or detected CPUs when unset). Larger requested degrees remain intact. The automatic minimum applies to full-text tasks; ordinary and multivalue index tasks retain their existing degree policy.
* FTS scans with the standard four-column projection and string document IDs emit a batch directly from one document's generated-postings cache. The batch ends before fetching the next document can reuse word buffers. Source visibility, tokenization and checksums retain their original per-document path. Numeric IDs used by hidden-primary-key tables and unfamiliar projections retain scalar output; the first experimental implementation failed hidden-PK DDL and was narrowed before submission.
* The rowkey/document-ID mapping subtask remains serial to preserve source-order ID allocation and the established implicit selection of equal-score documents below LIMIT. Subsequent postings tasks use the selected build degree.
* A direct COUNT(*) over a limited single-table view can skip the implicit full-text relevance order when the parent observes only cardinality. Explicit ordering, value consumers, joins, upper predicates and side effects retain the original path. Small consumer requests also bound document cache lookup batches.
* Parallel mapping exposed an existing top-k defect: BMW's fixed-size heap discards score ties, and the DAS sort iterator also caps returned rows at the limit even when its sort retains ties. Retrieval top-k pushdown is therefore disabled when there are secondary sort keys or FETCH WITH TIES; the full outer sort receives all scored rows. Regression tests derive expected top rows from all full-scan scores and retain the original defective baseline rows in their diagnostic reports; other baseline comparisons remain exact.

The range-planning direction was informed by the Apache-2.0 implementation in https://github.com/oceanbase/seekdb/pull/2047 by buGanFor, commit 1223d0f7d5946325e2eb9bb87ce10bdbefb53cb3. Our memo uses exact keys and dictionary invalidation, rather than a hash-only key or time-based dictionary freshness assumption.

Native correctness, performance and platform scores must be recorded independently. This document does not claim an unmeasured speedup or a platform score.

The long-document regression compares complete row IDs between incremental DML indexes and post-build indexes, then checks exact floating-point score representations against each path's frozen scalar baseline. Its 2,051 distinct words cross posting batch boundaries. The original baseline itself produces different BM25 estimates for the two construction paths, so the regression preserves and compares those two baseline score streams separately. It also checks updates, deletes, uncommitted reads and rollback. This supplements the existing hidden/composite-primary-key, ranking, tokenizer, shared-DDL and official-suite checks.
