# 六项本地实现

基线是现有 ltc dccb61e，当前修改叠加在本地工作目录，未创建提交、推送或调用平台提测。下列收益来自新实现与该基线的成对测量，和此前对更旧版本的比较分开。

| 项目 | 已实现的机制 | 保留条件与代价 |
| --- | --- | --- |
| 压缩缓存准入 | 先按候选表示估算大小；FP32 超预算时允许无损字节表示进入缓存 | 受整数内核实际可用性约束。编码失败且 FP32 放不下时释放并回退；可回退时先释放压缩数组，再重读此前行，避免同时保留两种大表示 |
| 过滤选择 | 首次扫描；随后以最多 256 行样本选择等值列。已建索引用实际区间行数，累计收益足够才更换 | 保持一个等值索引，切换前撤销旧分组。重排向量与范数，主键、标量和负零位图保留原行对应关系 |
| 普通列按成本缓存 | 最多 256KiB 廉价整数列随向量读取；WHERE 所需字符串按需加入；其他投影列最终 K 行回表 | 完全延迟所有普通列曾使过滤场景退化，修正后减少重复 WAL 扫描。超预算列回退读行，不无限扩充缓存 |
| 缓存复用与摊销 | 全局 8MiB 总预算内保存多个表的 LRU 缓存；表写入只失效该表 | 观察到每次改动后只有一次查询时，下一周期首查暂不构建，第二查恢复构建。该短周期策略的原生收益较小 |
| ANN 路径选择 | 32 维及以上已有缓存时，用最多 64 个候选估计第一坐标剪枝；剪枝弱则执行精确扫描 | 低维原有 ANN 行为保留，explicit exact 始终精确。抽样与少量候选距离有额外成本 |
| WAL 与恢复 | 日志达到检查阈值且历史显著多于有效行时，同步构建仅含有效行的 WAL | 提交边界外执行；临时文件同步、原子替换、目录同步后再更新行引用；保留原编码。每 256 行设置提交边界，限制恢复撤销记录。首次压缩有时间、额外写入与临时双份磁盘成本 |

原生三轮对照（macOS arm64，含缓存构建和 80 次查询序列及对应更新，过滤组检查 79 次）：

| 场景 | ltc 中位秒数 | 当前中位秒数 | 比值 |
| --- | ---: | ---: | ---: |
| 宽字符串列与小 K 投影 | 0.582035 | 0.024144 | 24.11× |
| 两张表交替检索 | 0.647977 | 0.036223 | 17.89× |
| 高维 ANN 请求 | 0.083962 | 0.060864 | 1.38× |
| 多等值条件过滤 | 0.028162 | 0.027106 | 1.04× |
| 每次写后仅一次查询 | 0.647758 | 0.643161 | 1.01×，接近波动 |

Mac 没有启用 x86 AVX2 整数路径，因此该平台的大表压缩准入场景没有可归因的新收益；Linux x86 结果另附。各组使用相同输入和查询序列，三轮交替运行，结果与独立暴力真值核对，未计算正式赛事得分。

历史日志样例从 14960662B 缩至 2493745B；压缩后重启就绪中位数从 0.031111s 降至 0.009343s。首次处理该历史日志的启动为 0.038655s，高于基线的 0.031277s。自动提交、显式提交、压缩中强杀、压缩后修改并强杀、残留不完整临时文件及重启均已检查。

行为回归覆盖 SQL、Unicode、事务与语句回滚、已确认提交后的崩溃、独立 TopK 真值、FP32 舍入、旧 WAL 格式、索引回滚与缓存可见性。另覆盖宽列回表、末行无法无损编码、分组索引双向切换及负零位模式。Linux 结果见下节。

原始报告位于工作区 `research/execution/2026-11-14-ltc-six-optimizations/`，包含源码摘要、原生三轮数据、首次退化结果及后续修正。当前平台分数未知。

## 本机 x86 Linux 结果

UTM x86_64 仿真，Ubuntu 24.04、2 vCPU。三轮交替执行，查询结果对照独立暴力真值；表中是六项组合版本与未修改 ltc 的比较，单项贡献未另行量化。

| 场景 | ltc 中位秒数 | 当前中位秒数 | 比值 |
| --- | ---: | ---: | ---: |
| 大表压缩缓存准入 | 7.313672 | 0.450235 | 16.24× |
| 多条件过滤 | 0.289002 | 0.197509 | 1.46× |
| 宽列小 K 投影 | 13.119700 | 0.277585 | 47.26× |
| 多表交替 | 2.897900 | 0.193497 | 14.98× |
| 每次写后仅一次查询 | 3.065784 | 1.890283 | 1.62× |
| 高维 ANN 请求 | 0.625875 | 0.272665 | 2.30× |

Linux 核心回归、60 条量化边界查询、双向分组切换与负零检查通过。52,476,221B 大数据量在 32MiB、零 swap 下重开、检索及全量排序通过；另在同一限额内核对了 20,000×128 的压缩缓存和末行普通 FP32 导致的拒绝回退。四个受限进程峰值为 33554432, 24096768, 4403200, 9523200B，均无 OOM 或 OOM kill。

Linux 本地构建使用缓存 GCC 13.3，源码 Dockerfile 指定 GCC 13.4 且保持原样。I/O 为来宾 cgroup 虚拟块设备计数；未测 Mac 实体 SSD。没有调用平台预检或正式提测。
